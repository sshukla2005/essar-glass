## 1. Summary of Completed Tasks

### Task 1 — Role-Based Access Control & Privilege Escalation Hardening
- **Dependencies**: Implemented `_require_roles(allowed)` dependency factory in `backend/app/routers/__init__.py`.
- **Router Configuration**: Configured `ROUTER_CONFIGS` in `backend/main.py`:
  - `/companies`: Read accessible by all logged-in users (`read_roles=None`), write restricted to `superadmin` (`write_roles={'superadmin'}`).
  - `/users`: Read restricted to `admin` & `superadmin` (`read_roles={'admin', 'superadmin'}`), write restricted to `superadmin` (`write_roles={'superadmin'}`).
- **Security Guards**:
  - **Superadmin Escalation**: Prevents non-superadmins from creating or promoting users to `superadmin` role (returns `403`).
  - **Self-Lockout**: Prevents users from modifying their own `is_active` status or `role` via `PUT /users/{id}` (returns `403`).
  - **Last Superadmin Protection**: Blocks deactivating or deleting the final remaining active `superadmin` in the system (returns `403`).

### Task 2 — NULL-Company Prevention & Backfill Migration
- **Alembic Migration (`b1c2d3e4f5a6_t2_backfill_user_company_id.py`)**:
  - Backfilled `users.company_id` for any NULL records to point to company `id=1` (lowest active company ID).
  - Queried NULL `company_id` counts across all company-scoped tables:
    - `customers`: **10** rows with `company_id IS NULL`
    - `employees`: **1** row with `company_id IS NULL`
    - `company_settings`: **4** rows with `company_id IS NULL`
    - *All other tables*: **0** NULL rows.
- **Backend Guard**: Updated `create_item` in `backend/app/routers/__init__.py` to raise `HTTPException(400, "No active company context — cannot create record")` when a company-scoped model is submitted without an active company context.
- **Seed Scripts**: Updated `seed.py` and `seed_full.py` to assign `company_id=1` to superadmin and require password environment variables.

### Task 3 — Document Number Integrity & Soft Deletion
- **Soft Delete Transition**: Updated `delete_item` in `make_crud_router()` so models with an `is_active` column perform a soft-delete (`is_active = False`) and return `{"message": "Deleted"}` instead of hard deleting.
- **Code Generation Compliance**: Added explicit locking documentation to `get_next_code()` in `backend/app/utils/helpers.py` ensuring soft-deleted rows are scanned so sequence numbers (e.g. `INV0042`) are never reissued (GST compliance).

### Task 4 — CORS & Middleware Registration Order
- **Middleware Reordering**: Swapped registration order in `backend/main.py` so `ReadOnlyMiddleware` is registered before `CORSMiddleware`.
- **CORS Outreach**: `CORSMiddleware` is now outermost and wraps all HTTP responses (including `403` responses generated by `ReadOnlyMiddleware`), allowing browser fetch calls to read details without CORS preflight blocks.

### Task 5 — Secrets & Environment Hygiene
- **Repository Hygiene**: Untracked `.env` from Git and updated `.env.example` with placeholders for all configuration parameters.
- **Alembic Credentials**: Cleared hardcoded `sqlalchemy.url` in `backend/alembic.ini`, ensuring Alembic reads `DATABASE_URL` strictly from `settings`.
- **Boot Assertions**: Added startup validations in `backend/app/config.py` asserting `len(SECRET_KEY) >= 32` and rejecting default secret key strings.
- **Rotation Guide**: Created `backend/SECRET_ROTATION.md` detailing OpenSSL secret key generation, environment updates, server restarts, and JWT invalidation warnings.

### Task 6 — Schema Auto-Creation Gating
- **Flag Control**: Gated `Base.metadata.create_all` in `backend/main.py` behind `AUTO_CREATE_TABLES` (`bool`, default `False`).
- **Documentation**: Updated `backend/readme.md` specifying Alembic migrations as mandatory for all database schema changes in production.
